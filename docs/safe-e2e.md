# Safe Integrations Hub draft application lifecycle

Use a dedicated test location whose owner has agreed to the installation. Keep the application `is_nonpublic=true` until moderation. Run each mutation with `mode=plan`, inspect its path/payload, then repeat with `mode=apply`.

1. Call `integrations_hub_list_developer_accounts`. Create an account only if none is suitable.
2. Call `integrations_hub_get_catalog_metadata` and `integrations_hub_list_available_rights`. Select the smallest permission set needed by the application.
3. Call `integrations_hub_create_application` with a stable alphanumeric slug, `is_nonpublic=true`, HTTPS callback/registration URLs, explicit countries, and minimal rights. Repeating the same slug is idempotent and returns the existing draft.
4. Call `integrations_hub_update_application` with the full card: long description, feature list, screenshots/video, FAQ, iframe/multi-location/privacy flags, callbacks, channels, and monetization. New icons and image promo materials may be supplied as `data:image/...;base64` data URLs and are uploaded by Biz.ERP. Omit `icon` to retain it; preserve every existing promo material because this is a full replacement. Video content is a reference/URL, not uploaded bytes. Review the replacement payload, then apply with `UPDATE APPLICATION <application_id>`.
5. If entity frames are needed, call `integrations_hub_replace_entity_frames` in plan mode. This is a full replacement: omitted slugs are deleted and an empty list deletes every declaration. Saving does not update existing installations; the values are copied only on the next installation. Keep every redirect on the declared URL origin or strict `postMessage` origin checks will break the iframe. Use `registration_redirect_url + is_iframe=true` for the separate Settings iframe.
6. Call `integrations_hub_grant_location_access` in plan mode as the test-location owner. Apply with `GRANT APPLICATION <application_id> ACCESS TO LOCATION <location_id>`. A normal public app becomes `pending`; an eligible private/draft app may fast-install to `active`.
7. If status is `pending`, call `integrations_hub_activate_installation` in plan mode within the current 12-hour window with entity webhook URLs and optional `chat_url`. Apply with `ACTIVATE APPLICATION <application_id> AT LOCATION <location_id>`. The callback links the system user and moves the installation to `active`.
8. Call `integrations_hub_get_installation_status` and verify `active`. This does not prove entity frames were materialized: location-wide limits are employee 1, client 1, visit 5 across all applications, and the current partner API has no effective-frame read endpoint. Retrieve the application token through the protected Developer Cabinet, then call one harmless Business Management API read using `Authorization: Bearer <partner>, User <application_token>` outside this server, or use Altegio Pro MCP. Verify callback delivery and iframe rendering in the application backend/UI.
9. Change one reversible card field with `integrations_hub_update_application`; review the full replacement plan, apply with its confirmation phrase, then read the app again and compare. Frame declarations are also full replacement, so always read them first.
10. To disable the test integration, call `integrations_hub_uninstall` in plan mode. Apply only with `UNINSTALL APPLICATION <application_id> FROM LOCATION <location_id>`. Verify `uninstalled` in the status log/list. Re-grant is required for a new install.

Normal owner publication flow stops after `integrations_hub_save_moderation_instructions` and `integrations_hub_submit_for_moderation`; human review remains an intentional product gate. This public MCP has no Marketplace administrator or publication tools.

Freeze has no partner command. It is driven by expiry/billing inside Biz.ERP. A successful `integrations_hub_record_payment` can unfreeze an eligible installation and must use a durable idempotency key.
